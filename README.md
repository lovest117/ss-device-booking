# SS Device Booking · 科室设备预约

一屏看每台设备的「已约 / 空闲」，直接下单、取消、查我的预约；每天 8:00 汇总当天设备，开始前 30 分钟提醒签到。运行时不依赖电脑、不依赖中间服务器，APK 内直连 `http://www.joyreserve.com`。

- 包名 `com.joyreserve.board`，版本 1.0.4，minSdk 26 / target 36（Android 16）
- 适配：Android 8.0+（minSdk 26），已在 Android 14 模拟器与 Android 16 真机验证
- 产物：`dist/joyreserve-board-1.0.4.apk`（debug 签名，可直接侧载）

## 一、怎么装

1. 把 `joyreserve-board-1.0.4.apk` 传到手机（微信文件传输 / 数据线均可，仅安装时用一次，运行时不需要电脑）。
2. 手机打开文件管理器点这个 APK；若被拦截：
   - 设置 → 安全 → 更多安全设置 → **安装未知应用**，给「文件管理 / 浏览器 / 微信」授权；
   - 弹出**纯净模式 / 增强防护 / 反诈提醒 / 未备案应用**时，选「仍要安装」「继续安装」。
3. 打开「设备预约」：首屏自动静默登录（右上角圆点绿色＝会话正常），随后逐台加载 6 台收藏设备的当日时段。
4. 首次启动会请求**通知权限**，务必点「允许」，否则 8:00 推送和签到提醒都收不到。

## 二、界面说明

| 区域 | 说明 |
|---|---|
| 顶部圆点 | 灰=未连、绿=已登录、红=异常、黄=读取中 |
| 日期条 | 今天起 15 天，超出平台开放范围不可选 |
| 收藏 / 全部 | 收藏 = 设置里打星的设备；全部 = 平台 44 台（非收藏设备点卡片才读取，避免一次 130+ 请求） |
| 时段轴 | 宽度按真实时长比例，每格标出整点小时（8、9、10…）；**灰=他人占用、绿=空闲、蓝=我的预约**、深绿=已勾选 |
| 点灰块 | 弹出该时段占用人姓名 + 手机号；点姓名或电话即可复制（顶部提示「已复制」） |
| 点绿块 | 加入/移出本次预约（支持不连续零散时段；应用不预拦，平台允许多少就约多少） |
| 底部操作条 | 显示已选段数与总时长，点「预约」填备注后提交；同一单只能同一台设备、同一天，跨设备/跨日期请分开下两单 |
| 我的预约 | **只显示未来的有效预约**；已取消、已结束的订单不显示（平台接口只返回最近 5 条） |
| 设置 | 账号/会话、收藏设备（打星）、提醒开关、运行环境、诊断日志与一键复制 |

### 提醒规则

- **每天 08:00**：汇总当天要开始的全部设备，一条通知推送（如「今天 2 台设备要开始」，正文列出设备与时段）。当天没有设备则不打扰。
- **开始前 30 分钟**：同一台设备的连续预约只提醒一次（例如 09:00-13:00 只在 08:30 提醒一次「30 分钟后开始：设备名」），设置 → 提醒 里可一键关闭。
- 提醒依赖系统闹钟，重启手机后会自动恢复。安卓 14 起「精确闹钟」默认关闭：首次启动会弹一次提示，设置页也有「去授权」入口，允许「闹钟与提醒」后 8:00 与提前 30 分钟才能准点；不授权也能用，但系统可能把提醒推迟（最长约 1 小时）。

## 三、实现要点

- **架构**：单 Activity + WebView 加载本地 H5（`assets/`），原生暴露 HTTP 桥 `JRBridge.http`，业务编排在 `assets/app.js`；推送与通知在 Java 层独立完成，H5 每次拉到订单后回传 `syncOrders` 供原生排提醒。
- **网络**：`HttpURLConnection` 单线程串行（避免 cookie 竞态、顺带限流），可自定义 `Referer`/`UA`、可关闭自动重定向拿 302、表单支持同名多值（`datesList[]`）。
- **会话**：cookie 存 `SharedPreferences`（按域名归一，`www` 与裸域共用），登录后 10 分钟免重登；失效自动重登一次。后台推送用同一份 cookie，过期会静默重登再取单。
- **接口链路**（严格复刻已验证顺序）：
  `GET /index.php/sjsw` → `POST /Wechat/User/login_in` → 每台设备预热（`confirm_disclaimer` + `one_room_private_booking_table`）→ `POST /API/Room/ajax_return_one_period_one_room_timestate` → `GET /Wechat/Booking/confirm_booking` → `POST /Wechat/Register/register_show`（`followRedirects=false`）→ 以 `my_register_more` 出现新单为成功准据。
- **推送**：`AlarmManager` 精确闹钟（安卓 14 首次启动弹一次授权提示；未授权时退化为不精确，设置页保留「去授权」入口）；`PushReceiver` 到点取最新订单→汇总当天设备→通知；签到提醒按「连续预约块」的开始时间−30 分钟挂一个闹钟（同设备连续 4 小时只响一次），开关关闭即全部撤销；`BootReceiver` 开机/升级后重建。
- **性能**：预热结果按房间缓存 8 分钟，一次刷新从 18 个请求降到 6 个，被拒时自动补预热重试；60 秒缓存 + 逐台渲染 + 顶部进度条；前台每 60 秒刷新，回前台补一次。
- **适配**：`usesCleartextTraffic` + 域名白名单；关闭算法变暗防深色反色；手动处理系统栏/挖孔/输入法 insets；不做常驻前台服务。

## 四、构建

0. 准备本地配置：`cp assets/config.example.js assets/config.js`，填入平台手机号与密码。`assets/config.js` 含账号信息，已被 `.gitignore` 排除，不要提交。
   仓库同样不包含 `keystore/` 签名密钥；`build.sh` 在缺少密钥时会自动生成一把新的调试签名。若要让新包覆盖旧安装，请在本机保留原 `keystore/jr-debug.keystore`。

本机无 Gradle，用 build-tools 直接出包（脚本 `build.sh`）：

```bash
# 依赖：JDK 17 + Android SDK（platforms;android-36 / build-tools;36.0.0）
./build.sh
# aapt2 compile → aapt2 link（含 assets）→ javac → d8 → zipalign → apksigner
```

签名用本地 `keystore/jr-debug.keystore`（口令 `android`，别名 `jrdebug`）；仓库不提交该文件。换机安装同一签名的包可直接覆盖升级，所以升级包务必保留原密钥。

## 五、排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 登录失败／顶部红点 | 未先建会话，或账号密码变 | 设置页「重新登录」；确认 `assets/config.js` |
| 「时段查询失败」 | 房间未预热 | 会自动补预热重试；仍失败点卡片「重试」 |
| 「确认页失败」 | Referer 或 td_id 格式错 | 看设置页日志的最后一条请求 |
| 「不可预约时段」 | 会话/房间上下文丢失 | 重新进入该设备后再提交 |
| 「请选择完整」 | 表单 hidden 字段缺失或一次性码过期 | 重开确认页再提交 |
| 「超出最多预约时段个数」 | 单笔超过平台表单上限（15 段） | 拆成两单 |
| 收不到 8:00 推送 | 通知权限被关 / 精确闹钟未授权 / 系统清理后台 | 设置页「提醒」按提示授权；荣耀机再把应用设为「允许后台活动」 |
| 收不到签到提醒 | 设置里开关关了，或该段距开始不足 30 分钟 | 打开开关；提醒只对未来的时段生效 |
| 提交后订单列表没刷新 | 服务端建单有延迟 | 等 5–10 秒下拉刷新「我的预约」 |
| 装不上 | 纯净模式/未知来源拦截 | 见第一节安装步骤 |
| 装好后点图标闪退/无反应 | 1.0.0 的旧问题（系统栏初始化早于页面创建） | 已由 1.0.1 修复，覆盖安装即可 |
